# Versus runs on Ably, with our server as the referee

Two friends race on Word Strike or Gap Guard in a private **room**. One makes it from the hub's VERSUS panel (a Word Strike room) or the versus panel its door opens, picking the minigame there, and shares its four-letter **room code** or link (`/versus/<code>`); the other joins, and both get the same prompts at the same time. The first right answer our server receives breaks the other player's heart.

**A room runs one minigame** (#37). It is picked with the Word Strike / Gap Guard switch in the Versus panel (default Word Strike) and stored on the room (`versus_room.minigame`; rooms made before the column are Word Strike). Every match and rematch in the room plays it. The room takes the saved difficulty (picked on the minigame cards) for either minigame and Word Strike's direction, which a Gap Guard room ignores. Gap Guard can't be picked when the pack has no askable gap sentences at that difficulty.

**Our server decides everything.** It deals the room's prompts (the minigame's shuffled draw within the room maker's difficulty, as solo deals it, fixed when the room is made: words for Word Strike, gap sentences for Gap Guard), checks each answer or pick with the pack's matching settings, and records each round in Postgres (`versus_room`, `versus_round`). A round's winner is written by one conditional `UPDATE` that only succeeds while the round has no outcome, so whichever right answer the database runs first wins and the other changes nothing. A wrong answer, or a wrong pick in Gap Guard, locks that player out of the round with no heart lost; if both are wrong, or the fuse runs out with nobody right, no heart breaks and the answer is revealed. The fuse starts at the solo start and is 1 s shorter for each heart broken, down to the solo floor. There is no server timer: when a round's deadline passes, either browser asks the server to catch up, which ends the round and deals the next one. Every step is safe to repeat.

**Ably carries the result to both browsers, and browsers never publish.** After every change the server publishes the whole room as one snapshot on the channel `versus:<code>`, over Ably's REST API. A browser gets a short-lived token from our server that may subscribe to its own room's channel and enter its presence, nothing else, as the client `versus:<code>:<seat>`. It speaks Ably's realtime protocol (v2, JSON) over the browser's own `WebSocket`, so there is no SDK to add. (#48 listened over server-sent events; #36 moved to the WebSocket because presence can't be entered over them.) Answers go to our server as server actions, never through Ably. Each snapshot is complete and numbered, so a missed message is repaired by the next one, and a browser whose connection is down asks the server every two seconds instead. A round's accepted answers reach the browser only with its result. A Gap Guard round's three options are in the snapshot from the start, in an order the server fixes for that round (sorted by a hash of the room's id, which browsers never see, with the match and round number), so both players see the same order and "first right pick" is a fair race; storing the order would have needed another column for the same result.

**The browser replays the snapshots through the solo duel reducer** (ADR 0002): an outcome is whose heart broke, or none. The reducer gained a versus flag (no stages, scores, combos or comebacks; the duel ends when either side runs out of hearts) and takes the fuse from the server. The duel screen draws the other player's hearts where solo draws stage progress (ADR 0005), and uses the room's minigame's own controls. A decided round reaches the reducer with its answers, so Gap Guard fills the gap in the sentence for both players and shows the player's pick against the answer.

**Ably presence tells the server who is still here** (#36). The server keeps no connections, so it asks Ably's REST API who is present whenever a browser asks it to catch up, once the match's first prompt has shown. Ably keeps an abruptly dropped connection present for 15 seconds, so a player who closes the tab or loses connection is gone 15 seconds later, and one who comes back sooner (a reload keeps the seat) never shows as gone; the rounds missed meanwhile play out as normal. When a browser sees the other seat's presence leave, it asks the server to catch up at once. A seat gone from presence, or that pressed MENU, has left the room: before the match is won that loses it ("Rival left: you win"), and it can't come back. After game over, a rival who has left turns REMATCH into "Rival left".

**A rematch is the next match in the same room** (#36). It needs both players to press REMATCH; the press that finds the other's already in starts it, in one transaction: the last match's rounds are deleted, a fresh draw is dealt with the same settings, and the countdown runs again. The room counts its matches, so each snapshot's number keeps growing across matches. A room closes as soon as both players have left, or 10 minutes after its last match ended unless a rematch starts.

**Guests and accounts both play** (ADR 0006, 0008). A seat is held by a secret the browser keeps for the tab; the room stores only its hash. An account lends its name to the room and nothing else; versus keeps no best score and nothing in word history. A room nobody joins expires after 30 minutes, a joined one after three hours, and expired rooms are deleted, rounds and all, whenever a new room is made.

## Considered options

- **Browsers publish to each other over Ably and agree on the winner.** Rejected: either browser could claim it answered first, and two clocks never agree on "first". One referee is simpler and can't be argued with.
- **WebSockets on our own server.** Rejected: Vercel functions don't hold connections open. Ably's free plan covers this, and our server stays stateless.
- **The Ably SDK in the browser.** Not needed: listening and being present is all a browser does, and Ably's realtime protocol over the browser's own `WebSocket` does both in a page of code.
- **Server-sent events** (what #48 shipped). Dropped in #36: they can listen but can't enter presence.
- **Our own heartbeat, browsers pinging the server.** Rejected: Ably already knows who is connected and waits the 15 seconds itself.
- **Judging answers by when the player typed them, adjusted for latency.** Left out: answers are judged by arrival at the server.
- **Gap Guard options shuffled in each browser.** Rejected (#37): the right option would sit in a different place for each player, so the race would partly be about where it landed.
- **Switching minigame between rematches, or matches that mix both.** Deferred to #69: a room runs one minigame for now.
